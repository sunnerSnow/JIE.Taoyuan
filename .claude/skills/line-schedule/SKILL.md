# 整理 LINE 行程公告

候選人 LINE 官方帳號（@589cjotf）用聊天推播公告行程，沒有公開網址、網站外也讀不到，只能由使用者貼上原文或截圖。這個 skill 把公告整理進 `web/src/data/schedule.ts`，`/trail` 最上面的「下一站行程預告」和一天一張的分享圖（`/trail/schedule/日期`）都從這份資料產生。

## 步驟

1. **讀公告**：公告一個日期一段，每場是「時間／活動／地點」三行。截圖看不清楚的字要問使用者，不要猜。
   完成條件：每場都有時間、活動、地點，字句和公告逐字相同。
2. **更新資料**：每個日期一筆 `ScheduleDay`，新的日期放最前面。同一天已經有資料時，整天換成最新公告（行程可能改時間或取消）。過去的日子留著。
   完成條件：公告裡的每個日期都在 `schedule.ts`，場次順序和公告一致。
3. **驗證**：在 `web/` 跑 `npx eslint`、`npx next build`、`npx tsc --noEmit`。用 `npx next start -p 3341` 打開 `/trail/schedule/<日期>` 看圖卡：字沒有壓到頁尾、場次多時整份清單會縮小。再看 `/trail` 的預告區塊（只顯示今天以後的日子）。結束後關掉 3341。
4. **回報與 commit**：貼出繁體中文 commit 訊息（不加 Co-Authored-By），使用者同意後才走 `/review-gate`、commit、push。

## 整理規則

- **照原文**：`title` 是「活動」，`place` 是「地點」括號前的部分，`address` 是括號裡的地址（沒有就不填），全形標點、數字照抄，不補公告沒有的字。`time` 寫 24 小時制 `HH:MM`。
- **只收行程本身**：聯絡電話、報名連結、呼籲文字不收。
- **預告不是紀錄**：行程結束後，等官方貼文或媒體報導再用 `/sync-official` 收進 `trail.ts`；LINE 公告不能當 `trail.ts` 的來源。
- **格式**：不要對既有檔案跑 prettier，原始碼一行大約 160 字寬。
